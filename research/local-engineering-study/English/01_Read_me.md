# Read me

The research question is how a local language model can complete engineering work reliably under consumer hardware constraints. This release provides bounded experimental evidence, including failures, rather than a population reliability guarantee.

1. Read [study protocol](02_Study_protocol.md) and [task contracts](03_Task_contracts.md).
2. Run the [offline record audit](04_Reproduction.md). It uses Python 3.11+ standard libraries and does not execute the model or UE.
3. Consult [asset and redistribution boundaries](05_Assets_and_licenses.md) before preparing a separate Windows model replication.
4. See [record lineage and limitations](06_Lineage_and_limits.md).

Four cohorts have separate schedules, requirements, freezes and scoring. The v7 cohort has 24 attempts on 12 author-constructed tasks; v8 has 4 attempts on 2 external defects; v9 has 8 attempts on 4 further Hessian defects; v10 has 96 attempts on 6 further defects across Express, Hexo and Hessian.js. Rates are not pooled. Published results must retain full denominators, including unsuccessful and unavailable terminal evaluations.

The v10 component study uses all eight combinations of interface (literal JSON/native functions), retained history (zero/two whole true action-result pairs) and task description (concise/explicit). Every cell has ordinary complete editable source and the same five offered tools. Two repetitions use the same greedy seed and fresh serving/candidate processes; they are not12 independent task samples.

Public records retain scores and numeric observations while replacing original machine roots and GPU identifiers. Public run locks bind derived record bytes and explicitly retain original result/terminal hashes. The original private records were not overwritten. No independent human review or Nature submission is implied by publication of this directory.

5. Inspect [PPL numeric records and exact input reconstruction](07_PPL_records_and_input.md).
